# Lessons ledger

One or two lines per lesson: slug, one sentence, an occurrence count, and a
task id or two (an id resolves to `tasks/<id>/RETRO.md`). /compound and
/lessons append new lessons or bump counts; two lines is the cap. Keep entries
SHORT - when a new occurrence adds a variant, sharpen the one sentence instead
of appending a paragraph. At three occurrences a lesson moves to Pending
promotions for the user to fold into a guideline, template, or tool. Counts
stay bare - (xN) - until a lifecycle event annotates them:
(xN, PROMOTED <date> -> <target>), (xN, absorbed by <tool or template>,
<date>), or (xN, RETIRED <date>: <reason>). Seeded 2026-07-16 from ~100
retros.

- `convention-and-checker-are-one-artifact` (x1): when the deliverable is a RULE, diff the prose's scope against the tool's matcher and name each gap an exemption or a bug -- a checker narrower than its wording is worse than none, since exit 0 reads as compliance. 20260731-172208.
- `fmt-runs-last` (x2): rustfmt reflows what you just wrote - an end-of-line comment after `{` or inside a multi-line call becomes an untagged BLOCK, and a narrowed `fn` signature collapses back to one line. Run fmt, THEN the checkers, after every edit round including review fixes; to label a magic number inside a construct, extract a named helper instead. 20260731-172223, 20260731-172224.
- `split-along-the-test-seam` (x1): when deciding whether to split a file, look at its test modules first - two that share no helper are a seam the author already found. Measure code-before-tests, not total lines: a 564-line file with 150 of code is one concern plus a rig. 20260731-172223.
- `record-numbers-from-a-rerun` (x3, PENDING PROMOTION): every count that lands in a record comes from re-running its command at write time, with the UNIT named - a file measured as 33 comment lines and 15 comment blocks is one file and two numbers, and writing either from memory of the reading pass mixes them. Cheapest guard: paste the per-file breakdown, so the total is reconstructible instead of asserted. The guard is easiest to apply to the number you expect to be challenged and easiest to skip on a downstream one that feels like bookkeeping - a file measured at 326 lines before a later edit shipped as 326 when it was 328. Third outing: a Close-out claimed the positive control produced 38 hits when the command printed 42 -- written from memory of a scrolled-past run, inside the very task promoting "probe, do not assert". 20260731-172224, 20260731-172233, 20260801-100108.
- `state-what-the-checker-cannot-see` (x3, PROMOTED 2026-08-01 -> `scripts/check-comment-tags.sh` rule 2, task 20260801-093730): when a pass takes a route its own project checker is blind to (test intent promoted to `///` inside `#[cfg(test)]`, which rustdoc never renders and the tag checker exempts), record the decision in the same commit and draw the line in the convention doc - an unstated legitimate route is indistinguishable from gaming the check. Then check your OWN diff against that line: on its second outing the same author put a value guard behind the `///`, which is the misuse the rule was written to stop. Authoring a convention does not confer compliance with it, and INHERITING one does not either - third outing, third author-side slip, one file where three magic inputs' justification went behind the `///` with the intent. 20260731-172224, 20260731-172232, 20260731-172233.
- `a-gotcha-needs-a-witness` (x1): a documented gotcha with no test exercising the path it warns about decays silently and keeps steering callers for the life of the fix. The `EventKind` derive default was documented as not resolving long after it was fixed, invisibly, because the repo's one derive site always passed the attribute. Treat every "always do X because Y is broken" note as a claim about current behaviour: find its executing witness or write one, and prefer a compile-time bound when the original defect was a compile failure. 20260731-172232.
- `probe-a-new-checker-both-ways` (x4, PROMOTED 2026-08-01 -> scripts/check-stale-refs.sh (task 20260801-100108)): before trusting a check script OR a measuring grep -- above all one that lands in a DoD proof -- probe it on a case it must match and one it must not; a clean run on real sources cannot reveal a matcher that silently covers less than intended, and correct neighbouring rows are not evidence about the row you have not probed. A `#[cfg(test)]` grep missed `#[cfg(all(test, not(target_arch = "wasm32")))]` and reported a 148-line file as 200 lines of code. Third outing: a `! grep -rn --include='*.md' ...` staleness proof omitted `*.html` and passed green over 18 surviving references -- red on the base branch proved nothing, since it was red for the hits it COULD see. Corollary: an `--include` allowlist fails silent, `--exclude-dir` fails loud; prefer the exclude form for whole-tree sweeps, and `git grep` when path prefixes are being filtered. Complements `regression-test-must-fail-without-fix` (red on a violation) with coverage. Fourth outing: rule 2 of the tag checker passed its own fixtures and a clean run over `src` while FOUR separate bugs made it skip whole test modules -- the probe that found them was a violation injected into a real repo file, not a fixture written alongside the code. A fixture suite the author wrote from the same mental model as the matcher tests that model, not the tree. 20260731-172208, 20260731-172232, 20260801-094300, 20260801-093730.
- `probe-the-argument-surface-too` (x1): when the deliverable IS a checker, its ARGUMENT surface is part of the matcher -- probe every argument empty, missing, mis-ordered and out-of-context before probing a single needle. `probe-a-new-checker-both-ways` is written entirely in matcher terms (all three of its occurrences were greps whose pattern covered too little), so its probes come out needle-shaped; both silent-clean bugs in the script promoting it entered through an argument instead. `-x ''` built the bare pathspec `:(exclude)`, excluding the whole tree and printing the all-clear, so `-x "$UNSET"` disabled the checker; and outside a repo `cd "$(git rev-parse --show-toplevel)"` became `cd ""`, whose `set -e` exit of 1 is indistinguishable from "hits found" -- fatal under the `! script <needle>` idiom the DoD itself used. Probing both ways is really three: match, no-match, tool error. 20260801-100108.
- `a-tree-scanner-scans-itself` (x1): a script that greps the repo greps its own source, so every literal path in its prose is a permanent hit for that path -- and a permanent false positive for the one check its user most wants to run. Use fictional example paths in usage comments, and run the file against its own examples before committing. The staleness gate shipped naming `docs/wasm-web-builds.md`, deleted by the immediately preceding task; the same self-scan hazard had already been reasoned about for the NEGATIVE control in the same header and still missed in the positive direction. 20260801-100108.
- `compute-a-complement-scope` (x1): a scope stated as a complement ("everything not claimed by the other children", "whatever the previous pass missed") is a QUERY - run it against the tree once and let its output be the enumeration, rather than hand-listing what you believe the complement contains. A KISS cluster planned and gated against its own ten-directory list; `src/material.rs` was claimed by no sibling, sat in nobody's list, and as the LAST task there was no downstream catcher - the epic-wide checker would have exited 1 after the epic closed. Corollary: when the project ships a checker, the final task in a multi-task cleanup runs it UNSCOPED at least once, since per-task path scoping is exactly what lets a gap hide from every task while staying visible to the whole. 20260731-172233.

- `a-silent-failure-mode-needs-a-self-check` (x1): when a tool's failure mode is SILENT -- it reports clean instead of reporting wrong -- neither reading it nor running it on real sources can find the bug, so give it an invariant it can check on ITSELF and make violating that invariant loud. A test-region rule tracked `#[cfg(test)]` by brace depth; four separate things miscounted braces (a lone lifetime tick read as a quote, a brace in comment prose, a brace in a raw string, a raw string spanning lines) and every one presented as exit 0 over the whole tree. Two were found by accident while writing a fixture for a different case. The fix that generalises is not the four patches but the invariant: a `.rs` file always balances to depth 0, so anything else is a TOOL error at exit 2, never a finding and never a clean run. Ask it at plan time, alongside `probe-a-new-checker-both-ways`: probing covers the cases you thought of, a self-check covers the ones you did not. 20260801-093730.

## Technical lessons

- `reuse-the-kit` (x2): Reuse the crate kit (TempEntity, glowing_material, ExplodeMesh, CameraShakeInput) end to end with zero new deps, and use HDR `glowing_material` so effects bloom -- unlit kills bloom. 20260705-101224.
- `try-entity-commands-for-fire-and-forget` (x2): For any "command applied to a stale entity" panic reach for `try_*` entity commands; to test cross-system ordering deterministically disable `auto_insert_apply_deferred`. 20260705-155230.
- `wasm-getrandom-and-build-profile` (x2): `rand` on wasm needs both `getrandom = { features = ["wasm_js"] }` and `--cfg getrandom_backend="wasm_js"`; `split-debuginfo = "unpacked"` + `debug = "line-tables-only"` halves test-build peak RAM. 20260703-000001, 20260703-000003.
- `size-limits-against-the-heaviest-config` (x1): a resource limit (job cap, memory budget, timeout) must be measured against the heaviest build configuration, not the default one. Sizing the cargo job cap on default features gave 7; `--features debug` links egui into every binary and busted the target at 18.4 GB, forcing 5. The default-feature number is informational, the worst case is the one that decides. 20260731-210044.
- `falsify-a-bound-with-a-subset` (x1): when a measurement claims to bound a whole, measure one part of it too -- a subset that exceeds the claimed total refutes it for free. A `cargo test` peak reported as 13.1 GB stood for a day; `cargo test --doc`, a strict subset, measured 16.4 GB at the same cap and withdrew it. The cheapest possible check on any single-run headline number. 20260731-210044.
- `bcs-no-full-test-suite` (x1): a bare `cargo test` here links ~76 full Bevy+avian binaries (1 lib + 15 examples + 60 doctests) and peak RAM is `(links in flight) x (binary size)`, so it exhausts a 31 GB box at cargo's default job count. Run it only under the `flake.nix` caps (`CARGO_BUILD_JOBS`/`RUST_TEST_THREADS`), and measure with `./scripts/sample-peak-rss.sh` rather than assuming. `RUST_TEST_THREADS` is the only lever on the doctest phase -- `[build] jobs` and `[profile.dev]` never reach rustdoc's harness. 20260703-000003, 20260731-210044.
- `release-gates` (x1): Version bevy_common_systems to Bevy's minor (0.19.x -> Bevy 0.19.x), and run cargo-about with an accepted-permissive set so generation fails on copyleft/unknown-license deps. 20260716-000016.
